## 2. 原始文件结构

每个股票目录包含三类 GB18030 CSV：

- `行情.csv`：十档行情快照。字段位置按文档固定，价格是整数价格乘 10000，数量单位为股，时间是 `hhmmssmmm`。
- `逐笔委托.csv`：委托事件。深圳委托类型 `0/1/U` 分别对应限价/市价/本方最优；上海 `A` 为正常委托、`D` 为撤单。买卖方向是 `B/S`。
- `逐笔成交.csv`：成交事件。成交价格同样除以 10000；成交量为股；买卖方向是 `B/S`。

深圳逐笔成交中的 `成交代码=C` 是撤单候选，不计入成交量、成交额或成交笔数。其非零的买卖委托引用用于关联委托。上海样本没有完整的撤单逐笔链路。

## 3. 订单簿构建方法

### 3.1 可直接使用的十档观测簿

最稳妥的主结果是把 `行情.csv` 当作交易所发布的十档观测快照：

1. 按股票和自然日读取并按交易所时间排序。
2. 时间按 `hhmmssmmm` 解析为毫秒；保留原始整数时间。
3. 对每个快照读取卖一至卖十的价格/数量和买一至买十的价格/数量。
4. 价格大于 0 才视为有效档位；0 价格视为缺失，不参与 mid、spread 和深度计算。
5. 计算 `mid=(ask1+bid1)/2`、`spread=ask1-bid1`、各前 k 档深度、`DI_k=(B_k-A_k)/(B_k+A_k)` 和加权中间价。
6. 标记 `valid_l1`、单边盘口、锁定盘口和交叉盘口；不要把缺失价 0 当作有效价格。
7. 3 秒网格使用 backward-asof：每个网格点只取此前最近快照，不做未来插值。连续竞价分为 09:30—11:30、13:00—15:00 两段，窗口不跨午休或隔夜。

### 3.2 逐笔事件驱动的订单簿

如果需要研究订单生命周期，可在十档观测簿之外建立事件簿：

1. 委托事件按股票、日期、频道和消息序号排序；若频道或跨流序列缺失，不能声称得到全市场唯一事件顺序。
2. 新委托按价格和时间进入订单队列，保留原始委托号、方向、价格、数量和委托类型。
3. 成交事件按成交记录关联的买卖委托号扣减剩余数量；成交价为 0 的深圳撤单记录不作为成交。
4. 深圳 `成交代码=C` 按非零买/卖委托引用扣减撤单数量，并记录撤单方向；上海没有同等完整的逐笔委托/撤单信息，不能从成交文件反推全部未成交挂单。
5. 数量守恒检查：初始委托量减成交量减撤单量不能为负；剩余量为正表示截至数据结束仍有未完成委托。
6. 从事件簿导出十档时，按价格优先、时间优先聚合同价位队列；无法确定先后时保留 `unknown_order` 或采用整体延后一桶的保守规则。
7. 事件时间相同但顺序未知时，预测特征使用严格小于锚点的事件，或整体延后一个网格，避免未来信息泄漏。

订单簿重建的验收应至少包括：委托号唯一性、成交买卖引用匹配率、撤单引用匹配率、数量守恒、盘口价格排序、锁定/交叉状态、集合竞价与连续竞价边界，以及截断到任意时间点时历史特征不被未来记录改变。

## 4. 聚合代码

主代码：

`/aidata/wentao/level2_agg_2025/aggregate_level2_day.py`

脚本特点：

- 读取一个日 `.7z` 包；指定股票时只解压指定股票。
- 解析 GB18030 CSV，不依赖 pandas。
- 生成 3 秒 backward-asof 特征网格。
- 生成 3/15/60/300 秒滚动成交、撤单和委托统计。
- 深圳 `C` 撤单从成交统计中排除。
- 默认删除临时解压目录；使用 `--keep-raw` 才保留。

复跑命令：

```bash
python /aidata/wentao/level2_agg_2025/aggregate_level2_day.py \
  --archive /aidata/wentao/market_data/202501/20250102.7z \
  --out /aidata/wentao/level2_agg_2025/pilot_20250102 \
  --date 20250102 \
  --symbols 000001.SZ 600000.SH
```

## 6. 已知限制

- 本次只聚合一天、两只股票，没有运行全年聚合。
- 当前结果是十档观测快照加事件窗口特征，不是声称完整恢复交易所全量订单簿。
- 上海缺少完整逐笔委托/撤单链路；深圳缺少可验证的跨频道全局顺序。
- `BS` 方向按供应商字段保留，不能未经验证等同于主动方方向。
- 3 秒端点特征是采样快照特征；它不等于完整事件级 OFI。
- 原始商业数据仍留在服务器压缩包中，未复制到交接目录。
